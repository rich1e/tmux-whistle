# 实时 Agent 菜单设计

日期：2026-10-30
状态：已批准（2026-10-30）

## 背景与问题

当前 `prefix + n` 通过 `cmd_menu` 一次性读取 `whistle_agent_windows`，再调用
`tmux display-menu` 绘制菜单。菜单打开后不会随 agent 状态变化更新，而状态栏会持续
重算，因此会出现「状态栏有 2 个 running，菜单只显示 1 个」的差异。

2026-10-30 的隔离 tmux 3.8 实验确认：

- 再次调用 `display-menu` 可以替换菜单内容。
- 替换后选中项重置到 `-C` 指定的位置。
- tmux 没有读取当前菜单选中项的接口，无法在重排后让高亮跟随原窗口。

实验使用的独立 server 与 socket 已清理。

## 目标

- 菜单保持打开时，自动反映最新的活动态、通知态、消息与列表顺序。
- 列表重排后，高亮仍跟随刷新前选中的窗口。
- 保留方向键、数字键、`a`～`q` 与回车；单独 `Esc` 用于退出。
- 保持现有跳转、已读与双通道语义。
- 保持 POSIX sh 与零第三方运行时依赖。

## 非目标

- 本期不支持鼠标点击、滚轮或鼠标选择。
- 不改变 agent 状态的采集方式，不从屏幕文本或进程列表猜测 running。
- 不改变状态栏、徽章、桌面通知与 hook 的状态语义。
- 不把菜单中的 running 改成 Braille 动画；菜单仍使用静态 `▶`。
- 不引入 Python、dialog、fzf 等运行时依赖。

## 已确认的交互行为

1. `prefix + n` 与 `tmux-whistle menu` 打开一个居中的 `display-popup`。标题
   `tmux-whistle` 画在弹窗内容首行，不依赖 tmux 3.3 才加入的 `display-popup -T`，
   从而继续支持项目声明的 tmux >= 3.2。
2. 菜单存活期间每 0.5 秒重新读取一次 `whistle_agent_windows` 的派生数据。
   这是 UI 层读取插件已有状态，不是新的 agent 状态探测或后台常驻轮询；菜单退出后
   不再读取。
3. 数据没有变化时不重绘；数据变化时更新状态、消息、键位与顺序。
4. 选中项以 **window id** 为身份，而不是以 session 名或行号为身份。同一 session 的
   不同窗口不会被合并为同一选中身份。
5. 刷新后若原窗口仍存在且仍位于 26 个可见项内，高亮跟随该窗口；若窗口已消失，
   高亮落到原位置附近仍有效的条目（原索引超出新列表时夹到最后一项）。若原窗口被
   重排到 26 个可见项之外，同样夹到附近的可见项；Enter 绝不允许跳转到不可见项。
6. 待处理项仍排在活动项之前，共用 `1`～`9`、`a`～`q` 的 26 个快捷键；超过 26 项时
   仍显示明确的溢出提示，不静默截断。
7. `Up` / `Down` 只在可跳转条目间移动，不停在溢出提示上；行为与原生菜单一致。
8. 数字或字母快捷键立即选择当前画面上的对应项；回车选择高亮项；单独的 `Esc`
   关闭菜单。`q` 是第 26 项的普通快捷键，不承担退出功能，未分配时不执行操作。
   方向键的 `Esc [ A/B` 序列不得被误判为单独 `Esc`。
9. 空列表仍提示「没有 agent 上报过状态」。无 attached client 时仍降级为纯文本列表，
   不因引入弹窗而失效。

## 实现方向

### 1. 用 popup 替代原生 menu

`cmd_menu` 不再把静态 argv 交给 `display-menu`，而是通过 `display-popup -E` 启动
插件自己的交互式菜单进程。弹窗进程直接读取终端按键、维护选中 window id 并绘制列表。
终端原始模式、光标与输出状态必须在正常退出、按键退出、信号退出时恢复。

### 2. 共用一份菜单数据与动作定义

菜单数据源仍为 `lib/core.sh` 的 `whistle_agent_windows`，不新增第二份状态聚合逻辑。
待处理/活动两遍扫描、快捷键分配与溢出规则应抽成共享的菜单模型，供交互 UI 与
`--menu-args` 调试输出共同使用，避免再次出现 `cmd_menu` 与 `cmd_menu_args` 分叉。

选中后的跳转与已读应复用现有 `cmd_clear -t <window> --select <pane>` 路径，不能另写
一套只清部分状态的逻辑。已读只清通知通道，绝不动活动通道。

### 3. 绘制与输入

弹窗内输出 ANSI 终端序列，而不是 tmux 的 `#[...]` 样式。默认状态色、选中高亮与
`@whistle_color_*` 配置仍应生效；至少完整支持当前默认的 `#RRGGBB` 形式，其他 tmux
颜色写法若无法可靠映射，应安全回退而不是输出非法转义序列。

按键解析只覆盖本期确认的键盘范围：方向键、Enter、数字、字母、q、Esc。刷新与按键
处理串行执行，避免同一帧上边刷新边跳转导致目标错位。

弹窗尺寸随终端与内容收敛；文本超宽时安全截断，不破坏边框、选中行或后续按键处理。

## 不变量与约束

- 活动通道与通知通道保持正交；菜单只是消费者。
- 不在菜单里新增任何状态写入点。
- 不使用 `[[ ]]`、bash 数组、`local -n`、`mapfile` 或 `$'...'`。
- 新函数临时变量使用独立命名空间前缀，避免 POSIX sh 的全局变量覆盖。
- 不把 `run-shell` 排进会阻塞 tmux 命令队列的 `\;` 链中间。
- `tmux show` 读取继续显式使用 `-v` 与正确作用域。
- 派生命令与显示文本继续经过既有消毒路径；插件自生成的 format/ANSI 片段不得误过
  `whistle_sanitize`。
- 不覆盖用户已有 tmux 配置或键绑定；`prefix + n` 的现有重绑与自愈机制保持不变。

## 测试与验收

### 自动化

- 菜单模型：待处理优先、26 键分配、溢出边界、空列表与多 pane 去重保持原覆盖。
- 选中身份：重排后按 window id 跟随；窗口消失后索引夹取；空列表不产生选择。
- 按键解析：Up/Down、数字、字母、Enter、单独 Esc、q 的第 26 项快捷键与未分配时
  无操作，以及方向键 Esc 序列。
- 交互链路：在隔离 tmux server 中打开弹窗，改变窗口状态后无需重开即可看到更新；
  重排后按 Enter 仍跳到原选中窗口。
- 已读回归：选择带通知且仍在 running 的窗口后，只清通知，活动仍为 running。
- 无 client 降级与 `--menu-args` 调试输出继续有测试。
- 全部交互测试使用独立 socket；teardown 必须 kill-server 并删除 socket 文件，最后运行
  `make check` 与 `check-no-stray-servers`。

测试驱动与伪终端工具属于开发依赖选择，由实现者根据现有 bats 结构决定；不得增加
插件运行时依赖。

### 人工验收

1. 打开菜单，让另一个 pane 从 idle 变为 running，0.5 秒级看到菜单更新。
2. 选中 dayfold，触发通知/活动状态导致列表重排，高亮仍跟随 dayfold。
3. 用数字键与回车分别跳转一次，目标均正确。
4. 用 Esc 退出，终端无残留乱码、光标正常、后续按键正常；列表不足 26 项时按 q
   不执行操作，满 26 项时 q 选择第 26 项。
5. 菜单打开期间关闭选中窗口，高亮退到邻近有效项，不崩溃。
6. 菜单退出后不再有周期性 `whistle_agent_windows` 调用或残留进程。

## 留给实现者的细节

- 菜单模型与 ANSI 渲染器的具体函数划分、文件放置及命名空间前缀。
- 非阻塞/超时读取按键的 POSIX 实现，以及终端恢复的具体安装点。
- 弹窗宽高计算与文本截断方式。
- 伪终端交互测试的驱动方式。

这些细节不得改变上面已确认的交互行为与状态语义。
